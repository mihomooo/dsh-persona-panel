# dsh-persona-panel 0.7.1

## 改：什么算「重要」，交回给模型自己判断

0.7.0 的提示词里，「技术上的经历要不要写进日记」被我写成了一道判据：下次遇到同样的事，我会不会因此走另一条路？会，才值得留字；还列了「查一下就知道的、一次就过的、纯流水账，不用写」。

这条判据是错的。它把「重要」压成了一个可以机械回答的问题，而不同的经历本来就会长出不同的理解——同一条坑，有人记住的是教训，有人记住的是当时的气。

现在改成：

- 技术上的事也一样：如果你觉得这一段经历对以后的我重要，可以写进 diary——踩进的坑、想通的门道、以后不该重蹈的做法都算。写的时候把「为什么」和「以后怎么做」写下来，不要只抄错误信息。
- 什么算重要，你自己判断：不同的经历会长出不同的理解。不用凑数，也不用因为「这是个技术细节」就把它划出去；反过来，别把整段日志搬进去。
- 还有一层跟判断无关：日记只有这一个工作区看得见，凡是别的会话、别的工作区也会撞上的，同一件事再写进 AGENTS.md。

第三句保留，因为它不是判断，是机制：日记的可见范围就在一个工作区里。

工具 `persona_remember` 的描述同步改了口气：不再是「只有会影响下次行为才写」，而是「我判断值不值得留给以后的我——什么算值得，我说了算」。

## 测试

- `demo/sweep-test.mjs`：删掉两条判据断言，换成 `prompt leaves "important" to my own judgement`。
- 18 个套件全绿（sweep 55 项）。

## 升级

```bash
dsh plugin --profile <profile> add https://github.com/mihomooo/dsh-persona-panel/releases/latest/download/dsh-persona-panel.tgz
```

装完**重启 DSH**：宿主侧（提示词、钩子、备份）都要重启才生效；数据不动，`~/.dsh/persona-panel/` 原样可用。
