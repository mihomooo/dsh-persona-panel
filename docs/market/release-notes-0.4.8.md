## 0.4.8

起因是别人拿仓库做了一次代码评审，四条里三条半成立。这一版修的是真问题：

- **记忆进系统提示前先压平**（评审第 1 条，属实）。之前人设、画像、事件的文本原样拼进提示，只做了长度截断，没有处理换行——一条带 `\n` 的记忆可以在提示里另起一段，读起来像指令。现在所有写入路径（四个工具、面板新增/编辑、导入拆出来的条目）统一过一遍：控制字符与零宽字符换成空格、空白压成单个空格、按字段截断（人设补充 800 / 画像 600 / 事件 600 / 日记 500 / 类目说明 300 / 称呼 40）。空行和列表结构因此不再能伪造。
- **README 不再承诺还没发生的事**（评审第 3 条，属实）。安装表原来写着「插件市场搜 persona panel」和「npm 安装」，可 PR 没提、包没发。现在市场一栏注明「已提交收录，合并后可用」，npm 一栏直接写「尚未发布」。
- **`demo/check-tarball.mjs` 的断言是真的错的**（评审第 4 条，属实）。它找 `inject:['slots']`，实际代码是 `inject: ['slots']`（有空格），所以永远报 MISSING。修了字符串，另外加了 bundle 清单、client 平台、main 文件、截图四项检查，并且**有缺失就以非零码退出**——只打印不失败的自检等于没有。
- 新增 `demo/clean-test.mjs`（13 项）：换行压平、零宽字符清除、超长截断、面板编辑同样过滤、工具写入同样过滤。

评审另外两条不算 bug，但值得记下来：

- **依赖 harness 内部结构**（第 2 条，部分属实）。`agent.session.header.cwd` 确实不是公开契约，是从 `prompt-debug.log` 反推出来的；`layout.selectPanel` 在客户端也是先 `typeof` 判断再用。失效时的退路是 `lastDir`，写错工作区的条目会带 `src: 'guess'` 标记，面板里能看到。这条是设计上的已知代价：没有公开 API 就只能在内部结构上加一层判断。
- **提示注入本身无法根治**（第 1 条的后半）。记忆插件的文本最终都要进模型上下文，压平换行能挡住「伪造段落」，挡不住「这段文字本身在教模型做事」。所以记录仍是可回溯的：每条都有来历，能撤回。

安装：

```bash
dsh plugin install https://github.com/mihomooo/dsh-persona-panel/releases/latest/download/dsh-persona-panel.tgz
```
