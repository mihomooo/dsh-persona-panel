# v0.5.3

两处「看起来保存了，其实没有」修好了，都是面板冒烟时在真界面上点出来的。

## 事件上限：没有工作区时不再静默丢弃

从侧边栏直接打开「记忆」、这个实例里还没有任何会话时，保存请求带的 `dir` 是空串。
宿主 `setCap()` 找不到工作区就直接 `return`——弹窗照常关闭，审计照常记一条 `settings`，
数字却哪儿都没写。

- 宿主：没有工作区时落进数据库默认值（`db.settings.eventsCap`），新建存储仍会继承它。
- 面板：这种情况下上限输入框**置灰**，下面写明「先打开一个会话再改：这个数属于具体工作区，
  现在这里没有工作区可写」，保存时也不再发送这个字段。宁可不存，也不假装存了。

## 首次引导：把「日记」也问一遍

日记默认是开的，从第一次对话就开始写，而它只能往下写、不能改也不能删。
可引导页只问了人设卡、画像、事件三项——想关的人在这一刻没有入口。

现在引导页有四个复选框（`self` / `user` / `event` / `diary`），宿主 `firstRun` 的白名单同步扩展。
他人画像仍然不问：那是多人场景才用的，默认关，放进引导只是噪音。

## 测试

- `demo/render-test.mjs`：引导页出现「日记」，无工作区时上限输入框 `disabled` 且带解释
